Reflections on Big Data and Cloud Computing

Taking CSE 231 this semester has been one of the most practical learning experiences in my college life. Before this course, big data and cloud computing were abstract buzzwords that I had only read about in news articles. Working directly with Apache Spark, both in batch mode for word counting and in structured streaming mode for live tweet analysis, turned those buzzwords into tools I can actually pick up and use.

The most important thing I learned is the value of the MapReduce paradigm expressed through Spark's RDD and DataFrame APIs. Lazy evaluation, transformations versus actions, lineage, and fault tolerance used to sound like textbook concepts; once I saw a Spark job split a text file into partitions, shuffle intermediate key-value pairs across the cluster, and aggregate counts in parallel, the theory finally clicked. I also gained hands-on respect for the cluster manager — understanding how executors, cores, and memory are negotiated helped me stop writing code that silently wastes cluster resources and start thinking about partition counts, broadcast joins, and checkpointing.

The impact of this technology on daily work and life is no longer hypothetical to me. Recommendation engines on shopping and short-video platforms, real-time fraud detection in mobile payments, traffic optimization in ride-hailing, and epidemic surveillance dashboards are all built on the same ideas I practiced in the labs. Even my personal study habits changed: I now keep notes and screenshots in cloud storage, version-control every assignment on a remote Git repository, and use a remote experimental environment to run heavy workloads instead of burning out my laptop fan.

In the future, I plan to apply big data and cloud computing to my graduation project, which will likely involve analyzing large-scale educational clickstream data to predict at-risk students. The streaming pipeline I built in Project 2, which ranks countries by tweet volume every ten seconds, is a perfect template for a near-real-time early-warning system. Beyond graduation, I am interested in joining a data engineering team and contributing to ETL pipelines that process terabytes of data per day.

Regarding the teaching of this course, I have a few suggestions. First, more guided debugging sessions on common Spark errors — out-of-memory exceptions, serialization issues, and small-file problems — would save students a lot of time. Second, integrating a short unit on cloud cost awareness would be valuable, because knowing when to cache, when to broadcast, and when to spill to disk is what separates a junior from a senior engineer. Finally, the hands-on projects were the highlight of the course; keeping them but tightening the rubric around documentation and reproducibility would make the learning outcomes even clearer. Overall, this course gave me both a solid technical foundation and the confidence to tackle real-world data problems, and I am grateful for the experience.
